# 线上自习室项目 · 评估与注意事项

> 评审对象：`docs/原始需求-自习室软件.txt`
> 结论：**可以做，而且这份方案本身质量不错**（功能分层清楚、有 MVP 闭环、有避坑清单）。真正的风险不在"能不能做"，而在**技术栈对个人业余开发偏重**，以及**实时同步 / 计时 / 统计**这三处的细节正确性。

---

## 一、一句话结论

| 维度 | 评估 |
|------|------|
| 可行性 | 完全可实现。MVP 闭环用现成技术，业余时间 2~4 周能跑通 |
| 最大亮点 | AI 智能体做陪伴 / 报告 / 计划，是自习室类产品里少见、容易做出差异化的点 |
| 最大风险 | 不是算法，是运维：WebSocket 长连接 + 计时准确性 + 跨时区统计 + 免费部署额度 |
| 核心建议 | 第一版**砍掉 PostgreSQL / Redis / LangChain**，用 SQLite + 进程内状态跑通闭环，确认手感后再升级 |
| 走向软件端 | 建议 Tauri（或 Electron）**复用同一套前端 + 同一套后端 API**，后端不用重写；桌面端才能真正做"锁机 / 防玩手机"，这是网页端永远做不到的增值点 |

## 二、原文档本身需要修正的地方

1. **第九节「开发排期」缺失**：目录里列了，正文却从"八、数据模型"直接跳到"十、关键避坑点"。排期需要补上（见本文第六节）。
2. **技术栈是"生产级"配置，不是"个人 MVP"配置**：PostgreSQL + Redis + LangChain + 前后端分离 + WebSocket + Web Worker 同时上，业余开发很容易卡在环境而不是功能上。
3. **`StudySession.mode` 没定义取值范围**：需要固定为 `pomodoro | countup`。
4. **`AgentMessage` 写"可选，也可存 Redis"**：但 Redis 会丢数据。学习计划、周报是**用户要长期回看的内容，必须落库**；只有"最近 N 轮对话上下文"适合放 Redis。
5. **没有定义"暂停"语义**：番茄钟暂停、正计时暂停，暂停期间算不算学习时长？这是统计口径问题，必须先定义。
6. **没有提到 WebSocket 鉴权**：浏览器 `new WebSocket()` **不能自定义 Header**，JWT 只能走 query 参数或首帧消息。这是必踩的坑。
7. **排行榜没定义统计窗口**：今日 / 本周按哪个时区切？并列如何排序？
8. **白噪音用音频文件有版权 + 体积双重问题**：建议改成 Web Audio API 实时合成（本项目已按此实现，零音频素材）。

## 三、技术栈对照建议（原方案 → 建议方案）

| 组件 | 原方案 | MVP 建议 | 理由 |
|------|--------|----------|------|
| 主库 | PostgreSQL | **SQLite** | 单文件零安装；SQLAlchemy 抽象不变，上线只改 `DATABASE_URL` 即可切 PG |
| 缓存 | Redis | **进程内字典 + 数据库兜底** | MVP 阶段 Redis 只用来存"谁在线"，而在线状态本来就依附 WebSocket 连接对象 |
| Agent 框架 | LangChain | **直接调 HTTP API** | 3 个智能体不值得引入 LangChain，几十行 httpx 足够，升级路径仍在 |
| LLM | DeepSeek / 通义 / GLM | 同上 + **本地模板兜底** | 不配 Key 也能演示，配了 Key 自动切到真实模型 |
| 部署 | Vercel + Railway | 本地内测 → 一台轻量 VPS | Vercel 免费版不支持后端长连接；Railway/Render 免费额度已收紧且会冷启动断连 |
| 认证库 | python-jose + passlib | **PyJWT + bcrypt** | python-jose 维护停滞且有安全告警；passlib 与 bcrypt 4.x 有已知兼容报错 |

> 更细的取舍理由见 `docs/技术选型说明.md`。

## 四、必须注意的坑（按重要性排序）

### 1. 计时准确性：前端计时永远不可信
切标签页、锁屏、休眠都会让 `setInterval` 漂移。原文档提到 Web Worker 是对的，但还不够：
- 开始专注时后端记录 `start_time`（UTC 时间戳），前端只负责展示；
- 结束时**由后端用 `now - start_time - 累计暂停时长` 计算 `duration`**，不采信前端传来的秒数；
- 断线重连后用服务端时间回填，避免刷时长作弊。

### 2. 暂停语义必须先定义
建议：**暂停时间不计入时长**。会话中维护 `paused_total`（累计暂停秒数）与 `paused_at`（本次暂停开始时刻）。番茄钟和正计时共用同一套口径，否则统计会分裂。

### 3. 时区：跨日统计是最容易被忽略的坑
- 数据库统一存 **UTC**；
- "今日 / 本周 / 热力图"必须按**用户本地时区**计算，否则晚上 8 点之后中国用户的数据会被算到"明天"；
- MVP 可统一按 `Asia/Shanghai` 处理，但代码要留出 `user.timezone` 的位置。本项目集中在 `backend/app/core/timeutil.py` 处理。

### 4. WebSocket 在线状态不能只信数据库
"在线人数 / 专注人数"来自内存连接管理器 + 心跳：
- 客户端每 25 秒发 `ping`，服务端超过 60 秒未收到就判定离线并广播；
- 服务重启内存态会清空，所以 `RoomMember.status` 要落库并记录 `last_seen`，重启后按 `last_seen` 清理脏数据。

### 5. WebSocket 鉴权（原文档未提）
浏览器 WebSocket 不支持自定义请求头，因此走 query 参数：
```
ws://host/ws/room/1?token=<JWT>
```
或连接后首帧发 `{"type":"auth","token":"..."}`，校验失败 `close(4401)`。本项目用 query 参数，并校验房间是否存在、是否已满。

### 6. 多进程 / 多实例会撕碎房间状态
Uvicorn 多 worker 或多副本部署时，内存里的 `ConnectionManager` 各管各的，同房间的人可能互相看不见。
- MVP：单 worker（`--workers 1`）；
- 上量后：Redis Pub/Sub 做广播——**这才是 Redis 真正该用的地方**，而不是存"谁在线"。

### 7. AI 的三个现实问题
- **成本**：免费项目必然被刷，Agent 接口必须限流（如每人每分钟 6 次）+ 单次 token 上限；
- **密钥安全**：LLM 的 API Key **只能在后端**，绝不能进前端 bundle；
- **合规**：面向公众提供生成式 AI 服务在国内涉及备案要求；自用/小范围内测问题不大，公开运营前需确认。

### 8. 浏览器音频自动播放策略
浏览器要求**用户手势之后**才允许播放音频，所以白噪音按钮必须由用户主动点击，且切到后台再回来要能恢复。用 Web Audio API 合成噪声还顺带解决了版权和几 MB 音频包体积问题。

### 9. 排行榜性能
不要实时全表扫。先按时间段聚合再排序，并对 `study_sessions(user_id, start_time)` 建索引。数据量小的时候 SQL 聚合完全够用，不要过早引入 Redis ZSET。

### 10. 并发与边界
- 房间人数上限：加入时用**条件判断 + 事务**，避免两人同时挤进最后一个座位；
- 房主退出 / 删房：官方常驻房间不可删；房主离开房间保留（MVP 不做转移）；
- 重复加入：`(room_id, user_id)` 唯一约束 + 幂等处理。

### 11. 免费部署的现实（别按宣传页做规划）
Railway 免费额度已基本取消；Render 免费实例会休眠，**休眠即断 WebSocket**；Vercel 免费版不支持后端长连接。"完全免费上线"在 2026 年已经很难，建议：
- 内测：本机 + 局域网 / 内网穿透；
- 上线：一台 2C2G 轻量云服务器（约百元/年）+ Nginx，成本可控且不用对抗冷启动；
- Nginx 必须配置 WebSocket 升级头与 `proxy_read_timeout`。

### 12. 安全基础项
JWT 密钥必须来自 `.env`（生产环境不能留默认值）、bcrypt 天然满足密码校验恒定时间、CORS 用白名单而非 `*`、WebSocket 消息做结构校验、写接口限流。

### 13. 断线重连体验
前端要自动重连（指数退避），重连后回填房间成员与当前计时状态，否则用户会看到"自己从房间消失了"。

## 五、从"网页端"到"软件端"的路径

架构上只要坚持一件事：**所有业务逻辑在后端，前端只做展示与输入**。这样：

| 阶段 | 形态 | 复用情况 |
|------|------|----------|
| 第一步 | Vue 3 网页 | 前端 100% |
| 第二步 | Tauri 桌面壳套同一份前端 | 前端约 95% 复用（额外处理窗口、托盘、开机自启） |
| 第三步 | 桌面专属能力：专注模式（屏蔽娱乐站点 / 全屏锁定）、系统级番茄钟通知、开机自启 | 新增，且是网页端永远做不到的卖点 |

选 Tauri 而非 Electron：安装包从约 150MB 降到约 10MB，内存占用低得多；代价是需要 Rust 环境。

## 六、建议的推进节奏（补上原文档缺失的"第九节"）

| 阶段 | 目标 | 产出 |
|------|------|------|
| 第 0 周 | 跑通骨架 | 注册登录 + 建房间 + 进出房间（本项目已提供） |

| 第 3 周 | 数据回看 | 学习记录 + 热力图 + 排行榜 |
| 第 4 周 | AI 亮点 | 陪伴鼓励 + 周报 + 学习计划拆解 |
| 第 5 周 | 打磨上线 | 断线重连、限流、部署、Nginx/WSS |
| 后续 | 增强体验 | 好友、小组 PK、动态广场、成就徽章、桌面通知 |
| 再后续 | 软件端 | Tauri 外壳 + 专注模式 |

## 七、本仓库已为你准备的内容

- 可运行的后端骨架：FastAPI + SQLAlchemy + JWT 认证 + WebSocket 房间管理 + Agent 接口
- 可运行的前端骨架：Vue 3 + Vite + Pinia + Router + WebSocket 封装 + Web Worker 计时 + Web Audio 白噪音
- AI Agent 做了**无 Key 兜底**：不配任何大模型 API 也能演示，配上 Key 自动切换到真实模型
- 数据库默认 SQLite，改一行环境变量即可切 PostgreSQL
- 运行方式见根目录 `README.md`
